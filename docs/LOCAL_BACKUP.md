# 全量本地备份与登录恢复

适用 WoW 1.12 / Turtle WoW，Lua 5.0。SuperWoW 提供 `ExportFile` / `ImportFile`；未安装时不创建本地文件，公会同步仍可运行。

## 数据列表入口

- **备份数据**：创建当前 DKP 团队的独立完整备份。
- **恢复最新数据**：读取当前团队有效的最新完整本地备份（D 文件和同步完整快照择新），校验成功后完整替换目标团队，并恢复记分设置。
- **自动备份**：业务内容改变后保存完整快照；异常恢复被拒绝时暂停，勾选状态保留。
- **导入指定版本**：输入新版 D 文件或 P 指针文件名，可带 `.txt`。确认后完整替换当前团队；不合并、不重放日志，也不支持旧 CSV 备份。

其他团队的分数、日志、大小号关系、底分和替补/装备历史保留。Boss 分值、自动加分模式等设置在插件中是共用设置，恢复时按备份还原；窗口位置等本机外观信息保留。

## 全量内容

D 文件同时保存目标团队的所有玩家及当前 DKP、初始底分、大小号绑定及临时绑定、全部奖惩/装备/Boss 自动加分日志、每日替补记录、装备历史、团队定义，以及记分和网站配置。没有活动记录的玩家也保存，跨天不裁剪记录。存在同版本的同步状态时，还保存主从角色、对象、授权和未完成的整库重置基准。

当前总分直接保存和恢复，不根据日志重新推算。业务结构含 `scope = 2`，每日替补与装备历史携带团队归属，恢复只替换目标团队的记录。

替补副本的备份保存已校验的主团队长业务快照及原主从关系；替补本机的组人/队长设置差异不会生成一份由替补署名的新主团版本。

## 文件格式与写入顺序

文件全部使用 ASCII 名称，位于 SuperWoW 的 `imports` 目录：

- `D-<身份校验值>-D<团队ID>-<日期>-<修订号>-<备份序号>.txt`：前缀 `ADKP-BACKUP3:`，含格式版本、角色/服务器身份、单份完整数据、版本、同步关系和内容校验值。
- `P-<身份校验值>-D<团队ID>-0/1.txt`：前缀 `ADKP-POINTER2:`，两个槽交替保存完整备份的指针。
- `P-<身份校验值>-D0-TEAMS-0/1.txt`：前缀 `ADKP-CATALOG2:`，保存团队 ID 列表与最近使用团队，便于 SavedVariables 和团队列表一起丢失时发现备份。
- `ADKP-SYNC-<身份校验值>-0/1.txt`：前缀 `ADKP-SYNC2:`，同步模块的完整状态检查点，继续作为本地恢复候选。

D 文件和同步检查点均自动选择最短的 LZW 压缩 + Base64、Base64 或百分号转义编码，正文首字母分别为 `Z/B/E`。沿用纯 Lua 5.0 有长度限制的编解码器；文件保持可安全写入的 ASCII 文本。网络和本地复用编码器，但包结构不同，本地文件没有网络分片和收发包头。

新 D 文件只保存一次当前完整业务快照，读取时从该快照补回同步状态中的引用。每个文件独立包含全量数据，无需读取历史文件或合并增量。首次同步未完成时仍保留网站导入基准，确保重启后能按顺序完成同步；仅在对端确认完整当前版本后省略旧基准，不裁剪任何活动记录，也不修改内存中的同步状态。

已经生成的完整 `ADKP-BACKUP2:` 和 `ADKP-SYNC1:` 文件仍可读取；新写入统一使用压缩格式。读取先校验文件封装，再校验完整快照和业务版本。

新 D 文件写入后读回，核对完整文本、解码结构和校验值；团队索引也写入并读回；最后发布 P 指针。指针发布前不会替换旧恢复入口。最新槽损坏时尝试另一个有效槽。文件只能作为数据解码，不执行 Lua。

自动写入失败后间隔 10 秒再试，保留有效旧文件；不在每帧连续写入和刷屏。

业务版本包括记分员、服务器、团队标识、活动批次、日期、当日修订号、团队 ID 和快照内容校验值。备份序号与业务修订号分开：重复手动备份不会虚增业务修订号。网站导入建立新批次，同日版本继续递增；跨午夜日期优先、序号从 1 开始。

旧 D/P CSV 文件和没有新版完整结构的检查点不参与恢复。CSV 文本导出仍可用于查看或上传，不作为完整数据库备份。

## 登录协调

1. 数据初始化完成后，只读检查当前团队以及独立索引中已保存的团队备份。比较保存的业务版本和实际内容；检查完成前暂停自动备份和文件检查点写入，普通记分暂缓。明确确认网站导入可直接开始新一轮。
2. 同时通过 GUILD 查询已关联对端，等待约 12 秒。无公会或对端离线也会完成本地检查。回复需通过真实发送者、原同步关系和团队校验。
3. 本地更新或本地与对端版本/内容一致时优先本地；有效对端更新时提示对端恢复。同版本但内容不同不能走“内容一致”的快速恢复路径。
4. 本地恢复提示：`检测到DKP记录异常，是否恢复自动备份的数据`，按钮为“是 / 否”。如果团队选择信息也丢失，会补充被发现的目标团队名称。
5. 接受后完整验证快照，在临时表中准备恢复，成功后替换目标团队并刷新界面。恢复保留原业务版本，不产生新的 D 备份；同步文件检查点可保存已恢复的完整状态。
6. 对端恢复仍需确认；本地存在更新/一致的快照时可免去全量传输。刚恢复后继续与对端核对。

## 拒绝恢复

拒绝后保留现有业务数据，允许主管理员继续记分，暂停受影响团队的自动备份和同步数据发布，不覆盖原本地文件。暂停标记保存在 `ADKP_BackupStore`，跨登录有效；状态栏显示“记录存在异常，自动备份已暂停”。替补副本本来只读的限制不因此解除。

本次登录不重复提示已经拒绝的同一候选版本。稍后出现更新候选可再次提示，但不能自动替换拒绝后新增的分数；点击接受仍表示完整替换当前数据。恢复成功或明确确认网站导入新一轮后解除暂停。

## 验证

```text
python tests/run_sync_tests.py --lua <Lua-5.0解释器路径>
python tests/simulate_raid_example.py --lua <Lua-5.0解释器路径>
```

回归覆盖无活动记录的底分、完整替换、多团队隔离、单文件独立恢复、压缩格式及校验损坏拒绝、之前全量格式读取、未确认基准保留、坏文件及失败写入、旧 CSV 拒绝、登录本地/对端排序、同版本内容分歧、拒绝后记分与跨登录保护、延迟回复需再次确认、团队列表丢失、无公会恢复及恢复不生成新备份。12 人活动模拟原始文件在 `docs/simulations/12-player-raid-compact/imports`，报告包含新旧备份体积对比。

仍需游戏内双客户端验证实际弹窗和 SuperWoW 文件读写。无法保证恢复从未成功保存到任何本地文件或对端的数据。

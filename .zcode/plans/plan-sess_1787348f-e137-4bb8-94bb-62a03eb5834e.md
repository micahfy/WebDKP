## 多团备份/恢复隔离方案（v2）

### 准则
- **文件名按团隔离**：用大写 marker `D1 / D2 / D3 ...`（数字取自 `ADKP_GetTableid()`，对应数据里的 `dkp_<N>` 字段）
- **SV 指针按团独立**：`WebDKP_Options["LatestBackup"][charKey][tableid]`，**只按数字 id 索引，绝不用团名**（避免脏数据）
- **写入端不变**：`ADKP_RestoreFromData` 仍用 `ADKP_GetTableid()` 当写入目标（本来就对）
- **id 保持可回收**（按你的决策）：接受删团再建同号团时旧团磁盘备份可能被新团读到这个权衡
- **手动导入加团 marker 警告**（按你的决策）
- **marker 放在角色名和日期之间**：让 `<日期>-<计数器>` 仍保持在末尾两段，二分查找 counter 的逻辑完全不用改
- **服务器名空格处理**（v2 新增）：把 `string.gsub(serverName, "%s", "-")` 改为 `string.gsub(serverName, "%s", "")`——直接去除空格，不再用 `-` 替代。角色名 `charName` 的处理保持现状（仍用 `-` 替代，不动）

### 新文件名格式
- 数据文件：`D-<服务器>-<角色>-D<N>-<YYYY-MM-DD-HHMMMM>`（例：`D-PVE-Micah-D2-2026-07-18-120000`）
- 指针文件：`P-<服务器>-<角色>-D<N>-<YYYY-MM-DD>-<计数器>`
- 服务器名清空格后嵌入，例：服务器 "Azeroth East" → 文件名里是 `AzerothEast`（不是 `Azeroth-East`）

### 改动 1：新增统一构造函数（消除散点字符串拼接）

在 `ADKP_BackupData` 之前新增三个本地辅助函数（一次性集中所有文件名拼装逻辑，避免散点）：

```lua
-- 把服务器名中的空格全部去掉（v2：不再用 - 替代）
local function adkp_CleanServerName(name)
    return string.gsub(name or "", "%s", "")
end

local function adkp_BuildDataFileName(serverName, charName, tableid)
    return "D-" .. serverName .. "-" .. charName .. "-D" .. tableid .. "-" .. date("%Y-%m-%d-%H%M%S")
end

local function adkp_BuildPointerName(serverName, charName, tableid, dateStr, counter)
    return "P-" .. serverName .. "-" .. charName .. "-D" .. tableid .. "-" .. dateStr .. "-" .. counter
end

-- 从文件名解析团 marker（D1/D2/...），用于手动导入警告。解析失败返回 nil。
local function adkp_ParseTableIdFromName(filename)
    if not filename then return nil end
    local _, _, tid = string.find(filename, "%-D(%d+)%-")
    return tid and tonumber(tid) or nil
end
```

> 备份/恢复入口在调用 helper 前都先 `serverName = adkp_CleanServerName(GetRealmName())`，charName 保持 `string.gsub(charName, "%s", "-")` 不变。

### 改动 2：`ADKP_BackupData`（行 153）

**a. 服务器名清洗改用新 helper（去除空格，不再替代为 `-`）；文件名带 marker：**
```lua
local serverName = adkp_CleanServerName(GetRealmName() or "未知服务器")
local charName = string.gsub(UnitName("player") or "未知角色", "%s", "-")
local tableid = ADKP_GetTableid()
local dataFileName = adkp_BuildDataFileName(serverName, charName, tableid)
```

**b. 指针计数器：从当前团的 SV 记录读，写入当前团的 SV 记录：**

原代码：`WebDKP_Options["LatestBackup"][charKey]` 当成一个对象。

改为：先取 `LatestBackup[charKey]`（可能是旧扁平结构或新嵌套结构），再取 `[tableid]`。

```lua
local latestBackup = WebDKP_Options["LatestBackup"][charKey]
-- 兼容：旧结构直接是 {Date=,Counter=,...}（无团维度）→ 视为团1
local teamBackup
if latestBackup and latestBackup[tableid] then
    teamBackup = latestBackup[tableid]   -- 新结构
elseif latestBackup and latestBackup.Date and not latestBackup[1] then
    teamBackup = latestBackup            -- 旧扁平结构（迁移前的状态）
end
```

计数器从 `teamBackup` 读，磁盘扫描文件名加 `D<N>`。

**c. 写指针：强制升级成新嵌套结构**
```lua
if not latestBackup or (latestBackup.Date and not latestBackup[1]) then
    -- 旧扁平结构 → 清掉重建为新结构容器
    WebDKP_Options["LatestBackup"][charKey] = {}
end
WebDKP_Options["LatestBackup"][charKey][tableid] = {
    ["Date"] = currentDate,
    ["Counter"] = counter,
    ["PointerFile"] = pointerFileName,
    ["DataFile"] = dataFileName
}
```

**d. 磁盘扫描循环**（行 199-206）：构造指针名的位置统一走 `adkp_BuildPointerName`，自动带 `D<N>`。

### 改动 3：`ADKP_RestoreData`（行 227）

**a. 服务器名清洗**：同样改用 `adkp_CleanServerName`，去掉空格。

**b. SV 校验**（行 247-260）：从 `LatestBackup[charKey][currentTable]` 读指针，旧扁平结构 fallback 到 `[1]`。

**c. `FileExists` 辅助函数**（行 264-270）：构造指针名通过 `adkp_BuildPointerName`，自动带 `D<N>`。

**d. 60 天扫描**（行 320-340）：天然只查当前团，因为 `FileExists` 带了 marker。

**e. 写入端不变**：`ADKP_RestoreFromData` 内部用 `ADKP_GetTableid()`（行 475），天然写回当前团。

**f. 团1的老文件兼容**：在 `FileExists` 内部，当 `tableid == 1` 时，除了查带 marker 的 `D1` 文件，**再 fallback 查一次无 marker 的老文件名**（`P-<服务器>-<角色>-<日期>-<计数器>`）。团2+ 不做此 fallback，绝不吃老文件。
   - 注意：fallback 用清洗后的服务器名（去空格版本）。若服务器名有空格，旧文件（用 `-` 替代）查不到；这是 v2 改动的已知权衡，Turtle WoW 服务器名通常无空格，实际不会触发。

### 改动 4：`ADKP_ImportSpecificVersion`（行 688）—— 加团 marker 警告

在读取文件成功后、判断文件类型之前，插入 marker 比对：

```lua
local fileTableId = adkp_ParseTableIdFromName(filename)
local currentTable = ADKP_GetTableid()
if fileTableId and fileTableId ~= currentTable then
    ADKP_Print("警告：文件 [" .. filename .. "] 属于团 D" .. fileTableId 
               .. "，当前是团 D" .. currentTable 
               .. "。导入后将写入当前团，请确认是否继续。")
end
```

仍然执行导入（你的决策是"加警告但不阻断"）。写回目标仍由 `ADKP_RestoreFromData` 内部的 `ADKP_GetTableid()` 决定，即当前团。

在第 3 步（清理替补队长）旁边加一段，清理该团的备份指针：

-- 清理该团在 SV 里的备份指针（避免删团后残留无效指针）
if WebDKP_Options and WebDKP_Options["LatestBackup"] then

### 改动 6：迁移逻辑（在 BackupData 内按需升级）

旧 SV 形如：
```lua
WebDKP_Options["LatestBackup"]["PVE-Micah"] = { Date=..., Counter=..., PointerFile=..., DataFile=... }
```

迁移到：
```lua
WebDKP_Options["LatestBackup"]["PVE-Micah"] = { [1] = { Date=..., Counter=..., ... } }
```

迁移触发点：在 `ADKP_BackupData` 内部按需升级（改动 2c 已涵盖——发现旧扁平结构时，写回就用新结构覆盖），**不在加载时主动迁移**，避免对从未备份过的角色做无谓初始化。

### v2 已知权衡（服务器名去空格）

- 若服务器名含空格（如 "Azeroth East"），改版前的旧备份文件用 `Azeroth-East` 命名，改版后扫描只会找 `AzerothEast`，**导致旧文件无法被"恢复最新"自动找到**。
- 影响：Turtle WoW 服务器名通常无空格，**实际几乎不会触发**。
- 缓解：用户若确有含空格服务器的旧备份，仍可通过 `ADKP_ImportSpecificVersion` 手动输入完整旧文件名（含 `-`）来取回——手动导入通道不依赖自动扫描。
